# 数据库升级说明

本轮只完成本地源码与离线H2验证，没有连接或迁移线上数据库。

已有MySQL库升级前应备份并在独立测试库演练。先核对历史Agent/照片迁移是否已执行，按当前实际表结构补齐，不能重复运行ADD COLUMN：

1. `20261024-agent.sql`：旧Agent请求字段（已有则跳过）。
2. `20261027-career.sql`：求职偏好、公司、岗位、投递与阶段事件表；索引语句只执行一次。
3. `20261027-input-snapshot.sql`：任务输入快照及扩展结果/报告为MEDIUMTEXT，容纳中文和公司来源资料。

已有H2文件库：停止服务并冷备份数据库，再以 `classpath:schema.sql,file:/发布目录/20261028-career-h2.sql` 初始化。schema.sql创建缺少的求职表，H2专用脚本幂等补齐输入快照CLOB字段；不要执行MySQL的MODIFY语法。旧照片数据不需要删除，应用不会继续提供照片API。

MySQL生产应使用明确的迁移流程，应用启动设置`SPRING_SQL_INIT_MODE=never`。仓库`schema.sql`保留H2可重复启动用的`CREATE INDEX IF NOT EXISTS`，MySQL8不支持这种索引语法；生产不能依赖这份文件每次自动执行。新建MySQL库可在空库导入时移除索引语句中的`IF NOT EXISTS`，或按正式迁移工具规范制作初始化迁移，再禁止自动初始化。

验证重点：原数据行数和所有权不变；新字段存在；原分析、版本/PDF可用；两个测试账号不能互读career资料；事务冲突能回滚；中文长快照和结果可完整保存。退回旧应用前也应保留本轮新增表与快照备份，不默认删除用户求职资料。
