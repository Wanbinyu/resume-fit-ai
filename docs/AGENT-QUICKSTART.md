# Resume Fit AI 工具型 Agent：运行与阅读指南

本次修改在 `G:\I_dont_now`。保留 Java/Spring AI、JWT、异步任务和简历版本体系。

## 运行

需要 Java 21。完成 `mvn -f backend/pom.xml package` 后，从项目根目录双击 `启动Agent工作台.cmd`，或执行：

```powershell
Set-Location G:\I_dont_now\backend
java -jar target/resume-fit-backend-0.1.0.jar --app.ai.demo-mode=false
```

打开 `http://localhost:8080/workspace.html`，注册/登录自己的账号。在左侧选择 PDF、DOC、DOCX 或 TXT 文件（最大 5MB），点击“导入并自动分析”。系统提取文字、保留段落、保存原始版本并自动启动分析。没有目标 JD 时先做简历体检和岗位方向分析，不计算岗位匹配分数；已选择/粘贴目标 JD 时直接做岗位匹配。手动粘贴仍保留在折叠区域中。

文件无法读取、扫描版 PDF 没有文字或提取结果超过 6000 字符时明确报错，不会静默截断或创建不完整简历。扫描版 PDF 目前需要先 OCR 或手动粘贴。文件只用于解析，保存的是识别文字和文件名，不保存原始文件副本。

可以点击“体检并分析岗位方向”重新体检，或补充岗位、可选城市/公司/年限和 JD 后运行岗位分析。自动分析失败时原始简历仍保留，可单独重试。历史报告支持“查看完整报告”，无需重复调用模型。

每次新分析还会展示两块内容：

- **当前简历更适合的岗位**：根据已有经历推荐最多三个方向，并展示适合原因、简历原文依据及待核实条件。证据不足则不强行推荐。它不代表实时招聘职位或录用概率。
- **向期望岗位调整的方向**：先在分析区填写“期望岗位”。建议分为突出已有经历、先核实再补充、后续学习与实践。只有岗位名时明确标注初步建议；提供具体 JD 后再结合要求细化。选择已保存 JD 且未填期望岗位时，使用该 JD 的标题。

推荐岗位与期望岗位可以不同。例如现有简历主要是 Java 后端课程项目，期望 AI 应用开发时，可以推荐 Java 后端方向，同时建议以后完成模型接入、RAG 或工具调用实践；不能把尚未完成的实践写成已有经历。

无搜索配置时，只有期望岗位也可点击“运行岗位分析”，先生成体检和初步方向；不需要搜索密钥。点击“体检并分析岗位方向”会保留期望岗位，但不使用 JD。导入文件时同样保留已填写的期望岗位。旧报告不会自动付费补全新字段，需重新分析后才有岗位方向内容。

岗位分析生成的排序草稿需先检查轨迹、证据与差距，再载入新版本编辑器，人工核实后点击“保存版本”。系统不会自动投递、发消息、发布或覆盖原始简历。

离线运行：把命令末尾改成 `--app.ai.demo-mode=true`。默认配置仍为 Demo，普通全栈启动脚本遵守该配置。新脚本显式开启真实模式。页面会显示实际模式。

Java 会从后端目录的 `../.env` 或项目根目录的 `.env` 加载配置。`AI_API_KEY` 优先，否则复用已有 `DEEPSEEK_API_KEY`；模型优先 `AI_MODEL`，否则 `DEEPSEEK_MODEL`。环境变量和命令行可覆盖文件。真实模式缺少密钥会拒绝启动；密钥只留在本机配置，不提交或打印。

Node 继续使用自己的 `PORT`（默认 3000）与现有 provider 配置。Java 改用 `BACKEND_PORT`（默认 8080），避免共享 `.env` 后把两项服务都启动到 3000。工作台由 Java 提供；本次没有把 Node 旧分析接口改成同一套 Agent。

直接运行 JAR 或普通全栈脚本时，默认数据库为内存 H2，重启后测试账号和数据会丢失。新增的 `启动Agent工作台.cmd` 使用文件 H2，数据保存在已被 Git 忽略的 `backend/data/agent-workspace*`，适合本地保存自己的账号和简历。已有 MySQL 部署先备份，再执行 `backend/migrations/20261024-agent.sql` 一次；本次没有连接或修改线上数据库。

## 修改并生成简历

阅读岗位方向和调整建议后，点击“按建议调整简历”，核实并编辑内容，再点击“另存新版本并预览简历”。也可以在“生成与下载简历”中选择已有版本，填写可选求职意向，预览并下载纯文字 PDF。原始简历和已有版本保留。

PDF 正文只使用所选已保存版本；未保存的内容需先保存。支持 A4 中文多页排版，不提供 Word 导出或上传文件的原样版式复刻。生成下载区默认收起。

导出需要支持中文的 TrueType 字体。Windows 默认尝试 `C:/Windows/Fonts/simhei.ttf`；Linux 请安装有授权的中文 TTF 并设置 `RESUME_FONT_PATH`。启动无需 Python、ONNX 或图片处理模型。

升级前备份数据库和上传目录。旧部署已经保存的图片数据可留在备份中，本次升级不执行删表或删除用户文件。

## 工作台展开与收起

点击每个功能区的标题栏，可以展开或收起。首次打开时，简历分析、当前岗位推荐、期望岗位调整方向、岗位 JD 对比默认展开；版本时间线、新建简历版本、版本对比、历史报告、体检补充内容、草稿和执行记录默认收起。左侧的简历列表和文件导入默认展开，保存岗位 JD 默认收起。

页面按“左侧选择/导入简历 → 右侧填写分析条件 → 查看岗位方向与 JD 对比 → 按需编辑版本”排列。宽屏下岗位推荐与调整方向并排展示，窄屏自动改为上下排列。城市、公司和经验条件放在“更多岗位条件”中。

展开状态会保存在当前浏览器，刷新后恢复个人选择。单纯收起不会清空当前输入，但刷新页面不会保留尚未保存的表单内容。点击版本“编辑”或“将草稿载入新版本编辑器”会自动展开编辑器并滚动定位。分析进度更新不会重建这些折叠区，也不会自动打开用户已收起的结果区。

## 搜索能力的实际范围

提供两种可替换的服务端适配：开源自建的 SearXNG，以及可选的 Tavily 托管 API。未配置时明确返回 `UNAVAILABLE`，保留粘贴 JD 的入口；没有结果返回 `EMPTY`，服务异常返回 `ERROR`。Mock 只用于测试。离线 Demo 会禁用所有外部搜索，即使本机已配置凭据也不会访问网络。

SearXNG 开源代码：<https://github.com/searxng/searxng>；部署文档：<https://docs.searxng.org/admin/installation.html>。它本身不要求购买 API 密钥，但需要运行服务的机器和网络，并受上游搜索引擎可用性约束。公共实例未必开放 JSON 接口或适合持续使用。本次仅完成适配与本机 Mock HTTP 验证，没有部署 SearXNG 服务，也没有验证公共实例的真实检索效果。

部署好服务后，在 SearXNG 的 `settings.yml` 中启用 `search.formats: [html, json]`，并在本项目根目录 `.env` 配置（地址按实际部署填写）：

```dotenv
JOB_SEARCH_PROVIDER=searxng
SEARXNG_BASE_URL=http://127.0.0.1:8888
```

这个地址仅能由部署者配置，可以指向自建的本机/内网服务，不能由用户或模型控制。服务器禁用重定向，并限制连接、工具超时和响应体大小；返回来源页仍不抓取。请使用可信的搜索服务地址。

另一种方式是设置 `JOB_SEARCH_PROVIDER=tavily` 和 `TAVILY_API_KEY`，服务器调用固定的 Tavily HTTPS API。`auto` 模式有 SearXNG 地址时优先使用它，否则尝试 Tavily。两个服务均未配置时，可以直接粘贴 JD 完整使用分析功能。

只把用户填写的岗位条件发给搜索服务，不发送简历，也不允许模型自由拼接查询。返回 URL、检索时间和 `SEARCH_EXCERPT` 类型；这些是搜索摘要，未验证为当前在招岗位或完整 JD。分析结果会标明 `analysisBasis` 和使用的 `selectedSourceId`。

`read_job_description` 只读取用户 JD 或本次搜索返回的来源 ID，不抓取任意 URL。因此这版没有通用网页抓取器，也不借用本机浏览器登录状态。登录墙/验证码后的岗位仍需用户合法提供 JD。

## 注册表与最小循环

旧代码：`tools.prepare()` 固定预处理 → `provider.generate()` 一次生成。旧 `maxSteps` 没有约束实际模型请求。

现在：`AiProvider.turn()` 一轮模型请求 → 模型返回 `tool_calls` → 注册表校验/执行 → 用原 `call ID` 构造 `ToolResponseMessage` → 再请求模型 → 返回报告或到达终止条件。

| 工具名 | 参数 | 程序执行的事 |
|---|---|---|
| `load_resume` | `{}` | 通过任务绑定的所有权校验读取简历 |
| `review_resume_structure` | `{}` | 仅在简历体检模式提供，检查结构线索、文字证据和待核实的表达问题 |
| `search_job_requirements` | `{}` | 使用已验证的用户岗位条件搜索，每任务最多一次 |
| `read_job_description` | `{"sourceId":"user"}` 或本次来源 ID | 读取 JD/搜索摘要，拒绝任意 URL |
| `match_resume_evidence` | `{}` | 关键词匹配、缺口、覆盖率和原文证据 |
| `draft_resume_changes` | `{}` | 保留原文段落内容，按相关性整理顺序，返回未保存草稿 |

阅读顺序：`ai/AgentToolRegistry.java` → `ai/ResumeOptimizationAgent.java` → `ai/SpringAiProvider.java` → `analysis/AnalysisWorker.java`，均位于 `backend/src/main/java/com/wanbinyu/resumefit/`。

注册表是名称、说明、JSON schema、执行函数的映射。schema 对模型说明如何调用；执行时还会校验未知字段、必填字段、类型、长度、重复键和 JSON 格式。白名单通过名称动态分发，模型不能指定任意 Java 方法。前置钩子检查取消、参数和权限；后置钩子记录状态并限制结果长度。

注册表不是安全沙箱。真正的权限来自 JWT 用户、任务所有权校验、工具闭包中绑定的 `requireOwned` 读取，以及不提供保存/发布/发送/shell 工具。提示注入仍可能影响模型文字报告，所以网页、JD、简历都标为不可信数据；报告建议须核实。程序生成的草稿只移动完整段落，不写入新的技术、公司、数字或经历。没有空行分段时，可能保留原文顺序。

关键词表是现有技术词表，只覆盖一部分技术要求；分数仅是文字覆盖率，不能代表完整 JD 匹配度、熟练度或录用概率。缺失词要询问用户是否有相关经历，不能直接补进简历。

## 预算与结束状态

默认最多 6 次模型请求、12 次工具调用、120 秒总时限、35 秒单次模型时限、15 秒单工具时限、1800 输出 token/轮。SDK 自动执行工具和自动重试均关闭，避免绕过外层预算。支持运行中取消，数据库条件更新避免完成结果覆盖取消状态。

默认 `AI_TOKEN_BUDGET=64000` 使用序列化消息及 schema 的 UTF-8 字节数，加上消息开销和最大输出，做保守预留上限；它不是实际 token 数或费用。长简历可能提前停止，可按成本需求设置预算（最高 200000）。真实响应的输入/输出 token 单独显示；未知时为 0，不虚报价格。供应商最终账单为准；已发送的请求即使取消也可能计费。

Agent 终止值包含 `COMPLETED`、`NEEDS_INPUT`、`BUDGET_EXHAUSTED`、`CANCELLED`、`TIMEOUT`、`MODEL_ERROR`、`TOOL_ERROR`、`INVALID_RESPONSE`。任务状态映射为成功、需补充、取消或失败。只有成功任务生成历史报告，任何任务都不会自动保存简历版本。

需补充信息时，用户修改岗位/JD 后新建一次任务；这版不保存多会话聊天记忆。进度和取消复用已有任务 API。尚未增加进程重启后的任务恢复或自动重试。

```powershell
mvn -f backend/pom.xml test

```

离线测试覆盖真实多轮结果回传与 call ID、正常工具、未知工具、坏参数、所有权失败、无搜索配置、Mock 搜索来源、模型异常、输出格式错误、实际轮次和工具预算、token 预留、超时、取消、重复调用 ID，以及不往草稿中添加缺失经历。

`AgentApiTest` 验证注册→创建简历→异步任务→报告→用户显式另存未发布版本，并测试跨用户拒绝和仅岗位无 JD 的降级流程。

真实模型测试默认跳过。只在明确要消耗少量额度时设置 `RF_REAL_MODEL_TEST=true`，运行 `mvn -f backend/pom.xml -Dtest=DeepSeekLiveTest test`；使用合成输入、最多 6 轮，不调用搜索或上传个人简历。普通测试强制 Demo 且关闭搜索凭据，不会意外使用真实模型。
