## 目标与交付范围

以“我的求职”为入口，围绕一个明确的简历版本完成：个人求职偏好 → 简历质量诊断 → 已保存岗位的证据匹配与排序 → 公司资料及来源核实 → 投递进度与下一步建议。注册表中的工具读取本人数据、计算可解释结果，模型负责组合工具和解释，不能任意写数据库或伪造来源。

岗位方向推荐与真实职位分开：保存的招聘职位及用户提供的完整 JD 可以评估；联网搜索保留来源与时间，只作为待核实摘要。没有证据就返回信息不足，不编造公司信誉分、在招状态、经历或指标。

## 实施顺序

1. **结构与基线**：保存源码快照；独立前端资源；拆分工具定义、执行校验与业务计算；梳理模块职责和本地启动方式。
2. **分析一致性**：分析明确绑定版本，并在创建任务时冻结简历/JD输入；保护跨用户访问；完善取消、队列拒绝与状态转换。
3. **求职领域**：求职档案、岗位池、公司来源证据、投递记录；约束输入、数量和并发版本；所有数据归属当前用户。
4. **注册工具 Agent**：增加个人档案、简历质量、岗位排序、公司证据与投递摘要工具；离线 Demo 与真实模型共用工具协议、预算和终止机制。
5. **产品入口**：中文“我的求职”页面，连接简历版本、偏好、岗位、公司和投递；复用现有登录、报告、编辑与PDF流程。
6. **独立审查与迭代**：运行原有测试及新增边界回归；实际浏览器检查登录、空态、保存、分析、取消和手机布局；修复发现的问题后再交付。

## 必须通过的边界

- 不同用户之间的简历、版本、岗位、公司、投递、任务互不可读写。
- 提交分析后修改版本不改变该任务输入；未保存编辑不能隐式进入分析。
- 空简历、无JD、无岗位、无公司资料、过期岗位、缺失薪资、缺失城市均有明确结果，不能默认通过或默认高分。
- 公司事实、用户评价和待核实线索保留原始来源、日期和类型；来源不足时不输出信誉好坏结论。
- 版本冲突、重复投递、非法状态、过长输入、危险URL、数据库条目上限有可理解错误。
- 用户取消后迟到模型结果不能覆盖终态；模型/工具超时、重复调用ID、预算耗尽和无效JSON有明确终止结果。
- 静态资源可在登录前加载；401与403行为分开；页面转义用户数据并抑制旧异步响应覆盖新选择。
- 离线测试不读取真实简历、不调用付费模型或外部搜索；真实搜索可用性与生产效果不由Mock测试推断。
